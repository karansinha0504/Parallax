## 1. Focus and glass hierarchy (replaces the old white-ring focus)

Reference: `mockups/parallax-tv-v7.html` and `mockups/parallax-phone-v7.html`. Engine and CSS source: `reference/slab/` (slab.js, slab.css, slab_tv.css, slab_ph.css, slab_ph.js). It is a browser prototype: port the behaviour, not the code.

**TV: a travelling glass slab.**
- One thick glass slab sits over the focused card. It slides to the next card, then follows it rigidly. Rim about 5px, see-through bevel (bright top-left, dark bottom-right), soft glow in the card's colours, card-shaped (corner radius copied from the card). The slab hugs the card's real bounds; the card magnifies about 1.06 from its left edge. No white ring.
- **Calm, no wobble.** Critically damped motion only: no overshoot on the slab, the card scale, row tracks, episode strips or section changes. In slab mode the old horizontal bounce curve is replaced by the smooth ease-out everywhere on TV.
- The slab glides straight to where the card will END UP (account for rows that are still sliding), not to the card's current position.
- Changing home section (vertical): the slab fades out and in on the new card, it does not travel across the page.
- Hierarchy: content glass (Cast and crew, Soundtrack, About, settings cards) has a **thin quiet edge**. Top bar and floating pieces have a **medium edge**. Only the focused item gets the **full thick slab**, a brighter fill and a glow. Unfocused panels on the movie page dim slightly.
- Clip the slab to its host (section, grid or screen) so it never draws over neighbours.

**Phone: no focus system.** Scroll and tap. One tap opens. No selected state, no focus ring, no travelling slab, no scroll-follow. Home pager cards, library bars and grid posters open directly on tap.
- Phone movie-grid hero is a passive banner that **cycles on its own every about 6.5s**: first last-played titles (kicker "Continue watching", Resume button), then up to five unwatched suggestions (kicker "Suggested for you", Play). Crossfade art and text. Runs only while that screen is visible.
- **Thick bevelled glass only on things that float above content**: header buttons and search field, the collapsed now-playing bar and its button, the bottom Media/Music dock, sheets, toasts, the A to Z bar. Everything else (now-playing controls, track lists, chips, cards, video player controls) uses the thinner v5 glass.

Performance: the slab's rim uses live blur. Keep it cheap on the onn box (idle when nothing moves; a static rim fallback if frames drop). Android version of the box was not yet checked.

## 2. Artwork sizes and slots (verify against live docs; TMDB `/configuration` returns exact sizes)

| Type | TMDB | fanart.tv |
|---|---|---|
| Poster | 2:3 (to 2000x3000) | about 1000x1426 |
| Backdrop | 16:9 (to 3840x2160) | 1920x1080 |
| Logo (PNG) | wide, varies | HD logo 800x310, logo 400x155 |
| Thumb / still | 16:9 | 1000x562 movies, 500x281 TV |
| Banner | none | 1000x185 |
| Clearart | none | HD clearart 1000x562 |
| Disc, album, artist | none | 1000x1000 |
| Cast photo | 2:3 | none |

- Every card has ONE fixed slot ratio. Art is cropped to fill only when the source is the right type (poster in a 2:3 slot); the 2:3 vs 1.43:1 difference between TMDB and fanart.tv posters is absorbed by this crop.
- The card sizes in the mockups are guesses. Replace them with these ratios before building. Slot-less types (banner, logo, disc, square album art) need card designs.
- Always provide a fallback per slot: other art of that kind, then a backdrop, then a gradient with the title.

## 3. Videos with no artwork (YouTube downloads, personal videos)

Order: sidecar image next to the file, then art embedded in the file (YouTube downloads made with an embedded thumbnail), then a TMDB/fanart match, then a grabbed frame, then a gradient with the title.
- **Frame grab:** `MediaMetadataRetriever.getFrameAtTime` (or a Media3 frame extractor) at about 10 to 30% of the duration; reject near-black frames and try up to five points; use `OPTION_CLOSEST_SYNC` for speed; honour the rotation flag (phone videos). Do it once while scanning, in the background, cache as JPEG in the app's own storage (not on the USB drive); show a placeholder until ready.
- **Never crop or zoom low-quality art.** Show the whole frame at its true aspect ratio (landscape or portrait) inside the normal slot, with bars at the sides or top and bottom. Bars are the same frame blurred and darkened, not flat black. The focus slab hugs the whole slot, not the picture.
- A little upscaling is welcome: at most about 1.5x with Lanczos plus a light sharpen, never past native size by more. Any heavier upscaler runs once at scan time, never live.

## 4. Music: two-way sync, remote play, metadata

**Two-way folder sync (phone and box).** One dedicated Parallax music folder on each (phone folder via the storage access framework; the USB drive on the box). Pair once by QR. When the phone is on the box's Wi-Fi, each side compares its file list (identified by an audio-only fingerprint, not filename, so retagging does not look like a new file) and copies only what the other lacks, both ways. Sync also runs when Parallax is opened on either device.
- Deletions never sync automatically: they go to a "Removed" list for confirmation (keep-everything philosophy).
- Same audio under another name is skipped; same name with different audio keeps both (one renamed).
- Incoming WAVs convert to 320 kbps MP3 before syncing. No quality warnings.
- The box must be awake with Parallax able to run for the phone to push; otherwise the phone queues and sends next time. Android TV cannot be woken over the network.

**Away from home (e.g. gym).** Sync the library (or chosen playlists) to the phone so it plays locally with no internet. Optional extra: remote streaming of anything not synced through Tailscale on both devices (no open ports, works behind CGNAT; fine for music, video depends on home upload speed). Do not use port forwarding or a public tunnel; do not build a server. Home internet type and upload speed unchecked. At home the phone and box are always on the same Wi-Fi, so this is secondary.

**Built-in metadata fetcher** (replaces running the beets command line; beets is Python and will not run on Android). The phone does the fetching because it has internet right after a download; the tagged file then syncs to the box. Songs added directly on the box are fetched by the box when online.
- Identify by audio fingerprint (AcoustID/Chromaprint), then tags from MusicBrainz and art from the Cover Art Archive. Indian music is weaker there: fall back to the iTunes and Deezer search APIs, and use the Gemini API to clean messy titles. Synced lyrics from LRCLIB.
- Confident matches apply automatically; unsure ones go to a small "Needs a look" tray with one-tap accept. Never overwrite tags that are already good. Offline: queue and run later.
- Copy the naming and tag rules from Karan's beets `config-template.yaml` in `music-toolkit/` so the app matches his existing cleanup.
